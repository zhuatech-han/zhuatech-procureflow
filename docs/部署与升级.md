# 部署与升级

知华科技（上海如静知华信息科技有限公司） · https://www.zhuatech.cn/ · 商业咨询微信 zhuatech / zhuatech2。

使用Java21、Maven3.9、Node24.19.0或以上、Docker Compose v2。运行`python3 scripts/init-env.py`生成本机凭据；默认8097端口，WEB_PORT可改，不要停止其他项目。MySQL8.4健康后启动后端，后端健康后启动Nginx。数据库不对宿主机公开。

应用数据库用户名procureflow，库名zhuatech_procureflow，JDBC驱动MariaDB Connector/J3.5.10。Compose数据库在隔离学习容器网络内使用sslMode=trust（TLS加密但不校验证书）；外部部署应使用受信证书及sslMode=verify-full，不要沿用学习环境的trust设置。直接本地开发可通过DATABASE_URL和DATABASE_USER覆盖，Compose默认数据库账号和库名固定为上述项目值。

学习环境仅127.0.0.1监听。正式私有化部署取得商业授权后另行配置HTTPS反向代理、COOKIE_SECURE=true、边界限流、数据库隔离、备份、审计保护与独立安全验收。没有自动证书或云平台生产部署。

备份在业务暂停期间执行，凭据留在容器环境中，不输出到命令日志：

```bash
docker compose exec -T mysql sh -c 'MYSQL_PWD="$MYSQL_ROOT_PASSWORD" mysqldump -uroot --single-transaction --routines zhuatech_procureflow' > procureflow-backup.sql
```

备份含业务敏感信息，只保存在受控位置，不提交Git。恢复到独立空库演练，核对Flyway历史、询价数量、报价版本与冻结建议；确认成功后再用于灾备。使用原数据库凭据恢复已有卷，修改.env不会重置MySQL密码。

升级新增版本迁移，不改V1。备份后替换镜像并执行`docker compose up -d --build --wait`，Flyway自动应用新迁移；迁移失败读后端日志、恢复独立备份并排查，不手动跳过。需要回退时恢复对应版本数据库与镜像，不让旧程序直接访问新结构。

停止保留数据：`docker compose down`。只有独立测试环境可以用明确项目名执行`down -v`清理其卷；学习或生产卷不可这样清理。

运行层采用官方maven:3.9-eclipse-temurin-21镜像内的Java21，并以独立非root账号运行应用；不依赖其他知华项目镜像。该运行层保留JDK和Maven工具，比专用JRE镜像占用更大，生产镜像精简应另行构建和验收。

驱动使用useMysqlMetadata=true和useCatalogTerm=CATALOG，与MySQLDialect配合；Hibernate显式引用数据库与表标识符，保持与迁移文件一致的大小写。本地更换库名时同步设置DATABASE_CATALOG。结构校验保持validate，不自动创建或修改表。驱动选项见[MariaDB官方连接说明](https://github.com/mariadb-corporation/mariadb-docs/blob/main/connectors/mariadb-connector-j/about-mariadb-connector-j.md)。
